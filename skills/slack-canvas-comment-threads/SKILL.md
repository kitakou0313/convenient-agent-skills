# Slack Canvas Comment Threads — Canvasコメントの網羅取得

SlackのCanvas URLを起点に、そのCanvasに付けられた「コメント」（Canvasのブロックに紐づく注釈コメント機能で、通常のチャンネルスレッドとは概念が異なる）を漏れなく洗い出し、網羅性を検証した上でリンクと内容の要約をユーザーに提示するスキル。

Canvasのコメント個別のURL/取得APIの仕様はSlackの公開ドキュメントに明記されていないが、Slack公式ヘルプは「コメントを含むCanvasをエクスポートすると、対応する file conversation メッセージへの参照が含まれる」と説明しており、これはSlackの2018年の変更ログ（file commentsがfile threadsに置き換えられた）の一般的な仕組みと整合する。すなわち**Canvasコメントは実体としてfile conversation上の通常のメッセージ/スレッドとして保持されている**可能性が高い。このスキルはSlack関連MCPツールのみを使い、ファイルのメタデータからそのfile conversationを解決し、スレッドをページネーションが尽きるまで辿ることで網羅性を担保する。

## 全体の流れ

1. **入力受け取りとURL解析**（Coding Agentが実施）— Canvas URLを受け取り、形式を検証する
2. **取得手段の判定**（Coding Agentが実施）— Slack関連MCPツールの有無を確認する
3. **file conversationの解決とコメントの網羅的取得**（Coding Agentが実施）— ページネーションを尽くして取得する
4. **各コメントスレッドの内容取得**（Coding Agentが実施）— 返信を最後まで取得する
5. **結果の提示**（Coding Agentが実施）— リンクと要約を列挙する

## Phase 1: 入力受け取りとURL解析

- ユーザーからCanvas URLを受け取る。未指定の場合は確認する
- URLが `https://<workspace>.slack.com/docs/<TEAM_ID>/<CANVAS_ID>` 形式（`TEAM_ID`は`T`始まり、`CANVAS_ID`は`F`始まり）であることを確認し、ワークスペースドメイン・`TEAM_ID`・`CANVAS_ID`を抽出する
- 通常のスレッド/メッセージパーマリンク（`https://<workspace>.slack.com/archives/<CHANNEL_ID>/p<TIMESTAMP>`形式）やチャンネルURLが渡された場合は、対象がCanvasではない旨を伝え、Canvas URLの再入力を確認する

## Phase 2: 取得手段の判定

- 利用可能なMCPツールの中に、Slack関連で以下の両方に使えるものが揃っているか動的に確認する（ツール名・説明文から判定し、特定のツール名を決め打ちしない）
  - ファイルのメタデータ取得（`files.info`相当。共有先チャンネル・コメントの元メッセージtsを含む）
  - メッセージ/スレッド取得（`conversations.history`/`conversations.replies`相当。cursorベースのページネーションに対応するもの）
- **試すのはSlack関連MCPツールのみとする。Slack Web APIへの直接リクエストやブラウザ操作は行わない**
- 必要なツールが揃っていない、またはどちらも呼び出しに失敗する場合は、実行不可であることをユーザーに明示し、Slack関連MCPサーバーの設定を案内した上で終了する

## Phase 3: file conversationの解決とコメントの網羅的取得

1. **ファイルメタデータの取得**: `CANVAS_ID`（ファイルID）を使ってファイルのメタデータを取得し、共有先チャンネル・コメントスレッドの元メッセージ（親ts）を特定する
2. **未確定点の実地確認**: 1つのCanvas内の複数の注釈コメントが単一スレッドの返信としてまとまるのか、ブロックごとに別々の親メッセージ（複数スレッド）になるのかはSlackの公開ドキュメント上確認できていない。決め打ちせず、実際に取得したメタデータのレスポンス形状を確認してから、単一スレッドか複数スレッドかを判断し、取得方針を決める
3. **複数スレッドの可能性がある場合**: 対象チャンネルの該当メッセージ群を横断的に確認し、Canvas由来のスレッドを漏れなく拾う
4. **ページネーションの完遂**: 各スレッドは `conversations.replies` 相当でページネーション（`cursor`/`has_more`等）を最後まで辿って取得する。**cursorが尽きたこと自体を網羅性の根拠とする**
5. **件数の突き合わせ**: 取得したメッセージ数と、メタデータ上の返信件数フィールド（存在する場合）を突き合わせ、不一致があれば再取得する

## Phase 4: 各コメントスレッドの内容取得

- 各スレッドの返信をページネーションが尽きるまで取得する
- レスポンス上の返信件数フィールド（存在する場合）と実際に抽出した件数を突き合わせ、一致するまで取得を続ける
- 突き合わせ手段が無い場合は、その旨を記録しておき、最終報告でその点を明示する

## Phase 5: 結果の提示

- 見つかったコメントスレッドごとに、「リンク＋本文内容の要約」をチャット内のテキストとして列挙する
- 網羅性検証の内容（何件見つけたか、どう突き合わせたか、差分の有無）を簡潔に添える
- 取得できなかった、または網羅性を確認しきれなかったコメントスレッドがあれば、その旨と理由を明示する

## エッジケース対応

- **Canvas URLではない入力**（通常のスレッドURL・チャンネルURL等）: 対象がCanvasでない旨を伝え、正しいURLを確認する
- **権限不足でCanvas/そのfile conversationにアクセスできない**（MCPツール側のスコープ不足等）: 必要なスコープ・権限を確認するようユーザーに促す
- **コメントが1件も無いCanvas**: その旨を報告して終了する
- **ファイルメタデータ上、共有先チャンネルやスレッド元メッセージが特定できない**（スタンドアロンCanvas等）: 判明した情報を提示した上で、ユーザーに追加情報（共有先チャンネル等）を確認する
- **同一コメントスレッドを複数チャンネル/複数メッセージ経路で重複検出した場合**: スレッドの一意なID/URLに基づき重複排除する
- **利用可能なSlack関連MCPツールが無い環境**: 実行不可であることを明示し、Slack関連MCPサーバーの設定を案内する
