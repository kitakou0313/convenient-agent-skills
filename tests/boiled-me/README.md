# boiled-me テスト

boiled-me が要約・凝縮のあとも**情報を落としていないか**を検証する。入力文書に埋め込んだ「アンカー語」が生成文章に残っているかを機械的に照合する。

## 実行

```bash
tests/boiled-me/run.sh                 # 全ケースを各3回実行
tests/boiled-me/run.sh -n 5 01 06      # 実行回数を5回にし、01・06で始まるケースだけ実行
AGENT_CMD="<agent-cli>" tests/boiled-me/run.sh
```

- `AGENT_CMD` は、**プロンプトを標準入力で受け取り、応答を標準出力に返す**コマンド（既定: `claude -p`）。Agent を差し替える箇所はここだけ
- プロンプトは `skills/boiled-me/SKILL.md` の全文と自動承認の指示、対象文書から組み立てる。Agent のスキル呼び出し機能には依存しない
- 自動承認モード: ソース種別は「テキスト」、Phase 3 は全OK、Phase 4 は初回案を承認、迷う項目は情報を残す側で判断する
- 1ケースにつき N 回（`-n`）実行する。ケースは直列に実行するため、全ケースで 10 × N 回 Agent を呼ぶ
- いずれかのケースが FAIL なら終了コード 1

## 生成文章の確認

出力は `tests/boiled-me/out/<timestamp>/` に保存する（`tests/*/out/` は `.gitignore` 済みで、Git の記録には残らない）。

| ファイル | 内容 |
|---|---|
| `summary.tsv` | 全ケースの判定と、種別ごとの通過数/総数 |
| `<case>/report.md` | **読む用**。アンカーごとの ○/×、入力文書、期待値、生成文章（run ごと）を1ファイルに並べたもの |
| `<case>/run-N.md` | Agent の生の応答 |
| `<case>/run-N.phase4.md` | 応答から抽出した要約案（照合の対象） |
| `<case>/run-N.phase3.md` | 応答から抽出した圧縮方針の概要 |
| `<case>/run-N.check` | 照合結果（TSV） |
| `<case>/run-N.err` | Agent コマンドの標準エラー |

機械照合では、言い換えによる意味の脱落は検出できない。`report.md` の生成文章を目視で確認すること。

## 判定

| 種別 | 扱い |
|---|---|
| `must` / `order` / `any` | 通過率が100%未満（N回のうち1回でも未通過）なら FAIL |
| `may` | 残存率の記録のみ。スキル改修前後の比較に使う |
| `format` | `<phase4>` タグで応答を抽出できたか。抽出できない場合は応答全体で照合する（記録のみ） |
| `idleak` | 要約案に内部ID（`C1`、`IC1`、`P1a`、`G1`、`S1` など）が漏れていないか（記録のみ。正規表現による簡易判定のため誤検知がありうる） |

## ケースの書き方

`cases/<番号>-<名前>/` に2つのファイルを置く。

- `input.md`: 入力文書。1ケースに1つの罠だけを仕込み、残すべき事実には**言い換えにくい固有の語**（コマンド、数値、固有名詞）を含める
- `expect.txt`: 期待値。1行1項目、`#` で始まる行はコメント

```
must: --force                # 必ず残る。1回でも欠けたら FAIL
may:  ポート開放の理由         # 残らなくてもよい。残存率のみ記録
any:  案A | 案B | 案C         # 列挙のうち1つ以上が残る
order: step-a < step-b        # 最初の出現位置がこの順になる（`<` 区切りで連鎖可）
```

アンカーは生成文章に対する**部分文字列の一致**で判定する（大文字小文字・空白は区別する）。

## ケース一覧

| # | 種別 | 仕込んだ罠 |
|---|---|---|
| 01 | 手順 | 順序依存。順序が崩れると成立しない |
| 02 | 手順 | 似ているが対象が違う2系統のステップ（重複として統合されてはならない） |
| 03 | 手順 | 実行に必須の数値・フラグが短い文に埋まっている |
| 04 | 列挙 | 独立した項目が多く、重複は1組だけ |
| 05 | 時系列 | 日時と出来事の順序に意味がある |
| 06 | 論証 | 従属前提グループ（片方だけ削ると支持が崩れる） |
| 07 | 論証 | 独立前提が複数あり、一部は削ってよい |
| 08 | 論証 | 中間結論を経由する連鎖（中間結論を削ると経路が切れる） |
| 09 | 混在 | 論証セグメントと手順セグメントが交互に並ぶ |
| 10 | ハイブリッド | 手順＋理由づけ（理由は省略可、ステップは省略不可） |

## 範囲外

ソース種別（ファイル、MCP、テキスト）ごとの Phase 5 の分岐、要望対応で Phase 3 に戻る経路、「重複の可能性あり」の確認分岐は、このテストの対象外。
