# Setup Loop — 実行・検証ループの構築と自律実行

Agentがあるタスクを「実行 → 検証 → 修正」のループで自律的に進めるために必要な要件を聞き取り、ループを構築して実行するスキル。

## 全体の流れ

1. **ループの構築**（計画フェーズで実施）— 実行・検証・終了条件を聞き取り、実行計画を作る
2. **ループ実行前準備** — 実行計画を元に、必要なコマンド・toolの事前確認を取得する
3. **ループの実行** — 実行計画の承認を依頼し、承認が得られたら終了条件を満たすまでループを実行する

## Phase 1: ループの構築（計画フェーズ）

まず、これから計画フェーズに入ることをユーザーに明示する（Tool内にPlan modeに切り替える機能を持つものがあれば必ず利用する）。
以下の3点をユーザーに質問して聞き取る。ユーザーの依頼内容から自明な項目は確認のみに留め、不明な点を重点的に聞くこと。

### 1-1. 実行についての聞き取り

- 実現したいタスクは何か（対象・ゴール）
- 実行に使うコマンド・手順・対象ファイル

### 1-2. 検証についての聞き取り

- 実行結果をどう検証するか
- 検証方法については複数あることを想定して確認すること
  - 検証したい軸が複数あることが考えられるため

**検証は必ず実装作業とは独立した文脈で実施すること。** ツールがサブエージェント・別プロセス・別セッションなど独立した実行手段を提供している場合はそれを使い、メインの実行者が実装、独立した検証者が検証と役割を分離することで検証の客観性を保つ。検証者には検証手順と合格基準のみを渡し、実装時の文脈（どう直したか・どう直したつもりか）は渡さない。そのような独立した実行手段がツールにない場合は、実装の文脈を含まない検証専用のプロンプトを新たに組み立てて評価させることで代替する。

### 1-3. 終了条件についての聞き取り

- 成功条件: 検証がどういう結果になればループを終了するか
- 検証の合格基準（何をもって「成功」とするか）
- 最大イテレーション数（検証の合格基準に達せずループを繰り返す場合の最大ループ数。未指定ならデフォルト10回を提案する）
- 上限到達時の扱い: ループを中断し、現状と残課題をユーザーに報告する

### 実行計画の作成

聞き取りが完了したら、以下を含む実行計画をまとめる:

- 実行手順（1イテレーションの内容）
- 検証手順（独立した検証者に渡すプロンプトの要点と合格基準）
- 終了条件（成功条件・最大イテレーション数）
- **ループ中に必要になるコマンド・tool の一覧**（Phase 2 の事前確認取得対象）

## Phase 2: ループ実行前準備

実行計画をユーザーに提示し、実行フェーズに進んでよいか明示的な承認を求める。

承認が得られたら、ループが承認待ちで中断しないよう、実行計画に挙げたコマンド・tool を **ループ開始前に1回ずつ実行（または安全な形で試行）** し、確認・承認が必要な操作をまとめて前倒しで処理する。

- 例: テストコマンド・ビルドコマンドを一度実行して承認を得る
- 破壊的なコマンドはこの段階では実行せず、ユーザーに事前承認（許可設定への追加など）を依頼する

## Phase 3: ループの実行

終了条件を満たすまで以下を繰り返す。ループの実行中はユーザーの確認を求めずに自律的に処理し続けることを重視する。

1. **実行**: Phase 1で定義した実行手順を1イテレーション分実施する
2. **検証**: 独立した検証者を起動し、検証手順と合格基準のみを渡して検証させる
3. **判定**:
   - 合格 → ループを終了し、結果をユーザーに報告する
   - 不合格 → 検証者の指摘を元に修正し、次のイテレーションへ進む
   - 最大イテレーション数に到達 → ループを中断し、現状・試したこと・残課題をユーザーに報告する

各イテレーションの終わりに「イテレーション番号 / 実行した内容 / 検証結果」を1〜2行でユーザーに報告する。
